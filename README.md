# Peripheral Planner

Итоговый проект по практическим занятиям №13-18 по дисциплине "Фронтенд и бэкенд разработка".

Проект выполнен как единое PWA-приложение на тему компьютерной периферии. Приложение помогает вести список задач по покупке, проверке и обслуживанию клавиатур, мышей, гарнитур, ковриков и другой периферии.

Ссылка на репозиторий: https://github.com/Max-kalashnikov/frontback3

## Отчет по практической работе №13: Service Worker

Цель работы: реализовать базовое офлайн-приложение со списком задач или заметок.

Что сделано:

- Создан интерфейс для добавления задач по компьютерной периферии.
- Реализован просмотр списка задач.
- Данные сохраняются в `localStorage`, поэтому не пропадают после перезагрузки страницы.
- Добавлена регистрация Service Worker в файле `public/app.js`.
- Создан файл `public/sw.js`, который кэширует статические ресурсы приложения.
- Проверена базовая офлайн-работа: App Shell и сохраненные задачи остаются доступными без сети.

Основные файлы:

- `public/index.html`
- `public/app.js`
- `public/sw.js`
- `public/content/home.html`

## Отчет по практической работе №14: Web App Manifest

Цель работы: доработать приложение до PWA с помощью Web App Manifest.

Что сделано:

- Создан файл `public/manifest.json`.
- В manifest добавлены поля `name`, `short_name`, `start_url`, `scope`, `display`, `background_color`, `theme_color`, `description`, `orientation`, `icons`.
- Подготовлены PNG-иконки разных размеров: 16, 32, 48, 128, 192 и 512 px.
- В `public/index.html` подключен manifest через `<link rel="manifest">`.
- Добавлены PWA-мета-теги для мобильных платформ и цвета темы.
- Service Worker кэширует manifest и иконки, чтобы они были доступны офлайн.

Основные файлы:

- `public/manifest.json`
- `public/icons/`
- `public/index.html`
- `public/sw.js`

## Отчет по практической работе №15: HTTPS + App Shell

Цель работы: реализовать архитектуру App Shell и предусмотреть запуск по HTTPS.

Что сделано:

- Приложение разделено на постоянный каркас и динамический контент.
- В `public/index.html` находится App Shell: шапка, навигация, статус соединения и контейнер для страниц.
- Динамические страницы вынесены в папку `public/content/`.
- Реализованы страницы:
  - `Задачи`
  - `Периферия`
  - `О нас`
- В `public/app.js` реализована загрузка страниц через `fetch`.
- В Service Worker для `/content/*` используется стратегия Network First: сначала сеть, затем кэш.
- В `server.js` добавлена автоматическая поддержка HTTPS, если рядом находятся файлы `localhost.pem` и `localhost-key.pem`.

Основные файлы:

## Отчет по практической работе №16: WebSocket + Push

Цель работы: добавить двустороннюю связь в реальном времени и push-уведомления.

Что сделано:

- Реализован сервер на Node.js и Express.
- Подключена библиотека Socket.IO.
- При добавлении обычной задачи клиент отправляет событие `newTask`.
- Сервер рассылает всем подключенным клиентам событие `taskAdded`.
- На клиенте показывается всплывающее сообщение о новой задаче.
- Добавлены кнопки "Включить уведомления" и "Отключить уведомления".
- Реализованы функции подписки и отписки от push-уведомлений через PushManager.
- На сервере добавлены эндпоинты:
  - `POST /subscribe`
  - `POST /unsubscribe`
  - `GET /vapid-public-key`
- Для push используется библиотека `web-push`.

Основные файлы:

- `server.js`
- `public/app.js`
- `public/sw.js`
- `public/index.html`

## Отчет по практической работе №17: Детализация Push

Цель работы: добавить напоминания и действия в push-уведомлениях.

Что сделано:

- На главной странице добавлена форма создания задачи с напоминанием.
- Для напоминания пользователь указывает текст и дату/время через `datetime-local`.
- Структура данных в `localStorage` расширена: каждая задача содержит `id`, `text`, `reminder`.
- При создании напоминания клиент отправляет на сервер событие `newReminder`.
- На сервере реализовано планирование напоминаний через `setTimeout`.
- Активные напоминания хранятся в `Map`.
- При наступлении времени сервер отправляет push-уведомление.
- В Service Worker добавлена обработка события `push`.
- В уведомление для напоминания добавлена кнопка "Отложить на 5 минут".
- В Service Worker реализована обработка `notificationclick`.
- Для откладывания напоминания добавлен эндпоинт `POST /snooze?reminderId=...`.

Основные файлы:

- `public/content/home.html`
- `public/app.js`
- `public/sw.js`
- `server.js`

## Запуск проекта

Установить зависимости:

```bash
npm install
```

Запустить сервер:

```bash
npm start
```

Открыть приложение:

```text
http://localhost:3001
```

Если в корне проекта есть файлы `localhost.pem` и `localhost-key.pem`, сервер автоматически запустится по HTTPS. Сертификаты можно создать через `mkcert`:

```bash
mkcert -install
mkcert localhost 127.0.0.1 ::1
```

## Проверка работоспособности

1. Открыть приложение в браузере.
2. Добавить несколько задач.
3. Перезагрузить страницу и убедиться, что задачи сохранились.
4. Проверить в DevTools разделы `Application -> Service Workers`, `Manifest`, `Cache Storage`.
5. Отключить сеть в DevTools и обновить страницу.
6. Убедиться, что App Shell и страницы открываются из кэша.
7. Открыть вторую вкладку и добавить задачу.
8. Проверить появление WebSocket-сообщения в другой вкладке.
9. Включить уведомления и создать задачу с напоминанием.
10. Проверить получение push-уведомления и кнопку "Отложить на 5 минут".
